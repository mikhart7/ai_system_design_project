# Мониторинг

## Технические метрики
- Latency hot path (guard + classifier) — цель P95 ≤500мс.
- Latency slow path (retrieval + генерация ответа) — отдельно.
- Ошибки/таймауты LLM API — отдельная метрика, триггер для отключения LLM (circuit breaker).
- Глубина очереди/backlog — особенно важно на всплесках нагрузки.

## ML-метрики
- Распределение уверенности классификатора во времени.
- Доля тикетов, ушедших на эскалацию из-за низкой уверенности.
- Reopen rate именно для автоответов (не общий) — если пользователь переоткрыл тикет после автоответа, ответ не решил проблему.

## Бизнес-метрики
- **North star**: доля тикетов, закрытых без оператора, без потери CSAT.
- **Guardrails**: reopen rate (не выше текущих 9%), CSAT (не ниже 4.2), доля тикетов с нарушением SLA (15 минут).

## Стоимость LLM
- Траты на LLM в день/неделю, порог бюджета с алертом.
- Доля тикетов, доходящих до LLM-вызова — если растёт быстрее общего трафика, значит фильтры (guard/риск-категории) стали пропускать больше, чем должны.

## Деградация модели vs изменение потока тикетов
- Уверенность падает, а состав категорий стабилен → похоже на деградацию модели.
- Уверенность падает вместе со сдвигом состава категорий (например, резко выросла доля `technical_bug` из-за сбоя) → это не модель "сломалась", а изменился сам поток обращений. Нужны новые примеры/FAQ, а не переобучение.

## Стартовые алерты
- Latency hot path P95 > 500мс.
- Ошибки/таймауты LLM > 10% за 5 минут.
- Доля low-confidence эскалаций выросла в 2 раза от обычной.
- Дневной бюджет на LLM превышен.
